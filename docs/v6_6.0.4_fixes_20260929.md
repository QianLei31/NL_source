## 数据流与文件兼容

`ThreadSafeQueue` 在内存中可附带 `StreamBlockInfo`，包含本块 epoch 与每帧的源序号。网络收到的字节、`ctre` 命令、ADC 低 12 位解释及 SPI 线协议保持原格式。

实时数据由 Hub 统一校正时间戳缺口。回放维护稀疏校正检查点，首次跳转到尚未索引的区域时在后台分块扫描。扫描按 4096 帧限额读取，支持取消，不把整个 BIN 放进内存。数据块和提交端都核对 epoch，避免 seek 前的在途数据进入 seek 后的缓冲。

`session.json` 保留 schema_version=1，新增可选字段：

- `source.frame_origin`：本录制首帧在源时间线中的位置；首块到达时即写回 manifest。
- `upstream_missing_frames`：扣除已知接收队列缺口后的上游缺帧估计。
- `timestamp_repeated_frames`、`timestamp_irregular_jumps`、`intra_frame_mismatch_frames`：本次录制期间的异常计数。

旧 manifest 缺失这些字段时按默认值加载。恒定高位的旧数据流不被自动当成可靠计数器；无时间戳文件仍按文件顺序解释相位。软件不能凭空恢复旧文件未记录的真实起始相位或无法判定的计数器跳变。

## MATLAB 导出

原来的 `ele0000_i32le.bin` 等 ADC 文件继续保留，新增：

```text
tdm_phase0_frames_i64le.bin
tdm_phase1_frames_i64le.bin
tdm_phase2_frames_i64le.bin
tdm_phase3_frames_i64le.bin
read_tdm_timeline.m
```

每个索引是 little-endian int64 的原始 ADC 帧序号。同一相位的 256 个电极共享一份索引，不必复制 1024 份时间数组。索引中保留已识别的缺帧位置。

```matlab
[codes, time_s, frame_index] = read_tdm_ele(folder, 64);
volts = double(codes) * 1.8 / 4096;
plot(time_s * 1000, volts);
xlabel('Time (ms)');
ylabel('ADC output (V)');
```

只要 ADC 数据的调用仍为 `codes = read_tdm_ele(folder, 64)`，旧接口继续有效。新的多通道 loader 还提供 `data.time_s{phase+1}`、`data.frame_index{phase+1}`、`data.is_uniform_phase`。`data.fs_hz` / `data.nominal_fs_hz` 是名义每电极采样率；发现缺口时应使用时间数组，不能把缺口前后直接当成均匀连续数据送入 FFT。

导出检查最终 flush，遇到写盘错误不再报告成功。独立 BIN 与 Session 分片使用一致的输入解析；损坏 Session、忽略残尾和缺帧都有错误或警告反馈。
