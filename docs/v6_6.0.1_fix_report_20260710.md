## 3. DataStore 与 RingBuffer 并发修复

### 3.1 原问题

Analyzer 的 `SorterWorker` 会在后台向 `DataStore` 追加数据，而 GUI 线程在 seek、切换通道或重建分析管线时会调用 `DataStore::reset()`。原实现直接读写同一个 `QMap`，存在容器被清空或替换时后台仍在访问的竞争条件。

此外，`RingBuffer::appendMany()` 在输入数据量大于容量时只保留最后一部分，同时只按保留数量增加 `m_totalWritten`。这会造成全局样本编号落后，进而影响时间轴和 TDM 奇偶相位。

### 3.2 修改内容

- `DataStore` 增加 `QReadWriteLock`。
- `reset()` 使用写锁，缓冲区查询和追加使用读锁。
- 新增 `sharedBuffer()`，Analyzer 绘图读取期间持有 `std::shared_ptr<RingBuffer>`，避免裸指针在 reset 后失效。
- `DataStore` 保存当前 timeline epoch。
- 新增 `appendChannelValuesIfEpoch()`，旧时间轴上的数据不能写入 seek 后的新缓冲区。
- `RingBuffer` 构造函数增加 `initialIndex`，允许回放从任意帧开始建立绝对样本索引。
- 批量输入被容量截断时，`m_totalWritten` 仍按完整输入数量增加。

## 4. 全局时间轴与 TDM 相位修复

### 4.1 原问题

原来的 TDM 分拣使用每个 TCP chunk 内部的 `frameIndex % 2`。如果 chunk 从奇数帧开始、队列丢失奇数帧、回放 seek 到奇数帧，L0/L2 或 L1/L3 的对应关系就可能整体翻转。

### 4.2 SessionHub 时间轴

`SessionHub` 现在维护：

- 当前分发位置 `m_currentFrameIndex`。
- 当前 timeline 起点 `m_timelineFrameOrigin`。
- timeline generation `m_timelineEpoch`。

新增 `addSubscriberWithFrameOrigin()`：

- 在分发锁内清空并注册订阅队列。
- 原子返回订阅开始时的下一帧绝对编号。
- 页面不再假设每次订阅都从帧 0 开始。

发生 seek 时：

- 清空 Hub 和所有订阅队列。
- 将当前帧位置及 timeline origin 设置为 seek 目标帧。
- 增加 timeline epoch。
- 通知各页面按目标帧重置缓存。

### 4.3 DataSorter 相位

`DataSorter` 新增：

- `m_nextFrameIndex`。
- timeline frame origin 指针。
- timeline epoch 检查。

TDM slot 现在使用：

```text
tdmSlot = (chunkStartFrame + frameIndex) & 1
```

Realtime 页面显示、Analyzer 页面 FFT/TDM 拆分和 Heatmap TDM 指标因此使用同一全局奇偶定义。

### 4.4 网络与回放分块

- 实时接收以 64 帧为标准队列批次。
- 正常接收期间不足 64 帧的完整数据暂存在 leftover 中。
- 接收结束时刷新最后一批完整帧，避免录制或显示漏掉尾部数据。
- 回放除最后一块外使用偶数帧 chunk。
- 队列在压力下丢弃整个偶数帧 chunk 时，不会改变后续 TDM 奇偶相位。

## 5. Heatmap 统计修复

### 5.1 原问题

原 Heatmap 的 mean、AC RMS 和 P2P 按任意 TCP chunk 计算。TCP chunk 大小取决于网络读取时机，同一个信号可能因为分块变化而显示不同统计结果。

同时，页面状态栏能够显示 dropped frames，但 `RealtimeStreamState::droppedFrames` 没有同步更新，Heatmap 的 packet-loss 状态可能一直不出现。

### 5.2 修改内容

- `RealtimeStreamState` 新增 `metricWindowFrames`。
- 默认使用约 100 ms 的固定统计窗口，最小为 64 帧。
- DataSorter 在多个 TCP chunk 之间累计统计量。
- 只有累计达到统计窗口后才发布一批新的 Heatmap metrics。
- 参考模式或 timeline epoch 改变时清空未完成的统计窗口。
- 饱和判断始终使用参考处理前的原始 ADC 电压。
- TDM 两个 slot 分别累计 mean、AC RMS、P2P 和饱和状态。
- Realtime 和 Sweep 页面把 SessionHub 的真实 dropped frames 写回 stream state。
- Sweep 页明确标记为“原始 ADC 全通道状态”，避免让用户误以为 Heatmap 已应用 Spike 页的通道滤波器。

## 6. Analyzer 动态配置修复

### 6.1 FFT 点数

原界面允许输入任意 256 的倍数，但后台会静默向下取 2 的幂。例如界面显示 2304，实际可能计算 2048。

现在 FFT 点数改为下拉选项，只允许：

```text
256, 512, 1024, 2048, ..., 262144
```

界面值、RingBuffer 容量和实际 FFT 点数保持一致。

### 6.2 运行中修改参数

以下操作在 Analyzer 正在运行时会安全停止旧 sorter、重建 DataStore、重新订阅 SessionHub 并继续运行：

- 修改通道文本并结束编辑。
- 从第一页载入通道。
- 修改波形点数。
- 修改 FFT 点数。
- 进入或退出 256 通道概览模式。

这样增加波形点数或 FFT 点数后不会继续使用容量不足的旧 RingBuffer。

### 6.3 采样率来源

- Session 运行时，Analyzer 的采样率由 SessionHub 决定。
- Analyzer 启动后采样率控件锁定。
- 停止后重新允许编辑。
- 避免页面采样率与实际流采样率不一致，导致频率轴和 FFT bin 错误。

### 6.4 256 通道概览

- 模式切换会记住普通模式下的通道、刷新率、波形点数、TDM 和 FFT 开关。
- 进入概览时使用 0.5 Hz、1024 点并关闭 FFT。
- 退出后恢复普通模式配置。
- 如果切换前正在运行，配置完成后自动重新启动处理管线。

## 7. FFT、SNDR 与 IRN 边界校验

正常参数下仍保持与参考 ADC Analyzer 算法兼容，包括：

- 输入去均值。
- Rect/Hann/Blackman/Blackman-Harris/Kaiser 窗。
- DC bin 排除。
- 信号 bin 积分。
- SNDR、ENOB、SNR、SFDR、THD、IRN 等统计。

新增非法配置检查：

- BW 不能超过 `fs/2`。
- BW 必须足够容纳峰值搜索区。
- 信号积分窗不能与 DC 排除区重叠。
- 信号积分窗不能越过配置的 BW。
- 信号/DC/谐波扣除后功率显著为负时，不再用极小正数强行生成虚假的高 SNDR/SNR。

IRN 显示继续使用：

```text
输入等效噪声 = 输出积分噪声 / Gain * 1e6
```

其中 Gain 为 Analyzer 中可配置的线性增益，`1e6` 仅用于转换为 `uVrms`。

## 8. Session manifest 与回放修复

### 8.1 严格 manifest 校验

如果 BIN 所在目录存在 `session.json`，现在必须通过以下检查：

- `schema_version == 1`。
- 256 通道。
- 每点 4 字节。
- 每帧 1024 字节。
- little-endian。
- sample rate 有效。
- parts 为有效数组。
- 分片路径不是绝对路径或目录穿越路径。
- 每个分片文件实际存在。

如果 manifest 损坏，回放会明确失败并显示原因，不再悄悄退化为只回放当前选择的一个 BIN。

### 8.2 跨分片回放

- ReplayController 将 manifest 中全部 part 按顺序组成一条连续数据流。
- seek 可以跨 part 定位。
- sample rate 优先取 manifest。
- 不完整 Session 会给出警告。
- 分片尾部不足一帧的数据会忽略并提示。

## 9. MATLAB 导出修复

### 9.1 三种导出模式

#### ADC12，默认模式

- 每个 ADC 通道输出一个 `ch###_i32le.bin`。
- 每个样本为 little-endian int32。
- 数值只保留原始 32-bit word 的低 12 位。
- 高 20 位时间戳被明确去除。

#### RAW32

- 用户勾选“保留原始32位（含时间戳）”后启用。
- 文件名为 `ch###_raw32le.bin`。
- 完整保留原始 32-bit word。
- MATLAB reader 使用 `uint32=>uint32`，避免时间戳最高位导致符号误解。

#### TDM Demux

- 输出 512 个映射后的电极文件。
- 文件名为 `ele####_i32le.bin`。
- 根据全局帧编号决定 even/odd slot。
- TDM 相位跨 chunk 和跨 Session part 连续。
- 每个输出样本只保留低 12 位 ADC。
- 同时生成 `tdm_map.tsv`、metadata 和 MATLAB loader。

### 9.2 跨分片导出

新增 MultiPartInput：

- 如果目录存在合法 `session.json`，导出 manifest 中的全部分片。
- 所有 part 被视为一条连续字节流。
- carry/leftover 可以跨 part 合并。
- `exportedFrames` 在 part 之间连续，保证 TDM 奇偶相位不重置。

### 9.3 后台导出关闭安全

- Export options 增加取消标志。
- RecordingPanel 析构时先设置取消，再等待后台任务收尾。
- 导出每 64 帧检查一次取消状态。
- 取消后不再继续遍历大型 BIN 文件。

## 10. 设置页面与端口处理

### 10.1 相同端点不再断流

`CommandCenterMainWindow::setEndpoint()` 现在先对 host/port/dataPort 做规范化和比较：

- 实际端点发生变化时才停止 SessionHub。
- 只保存设置、修改主题或重复应用相同端点时不会断开当前采集。

### 10.2 端口检测不再阻塞 UI

原“连接”按钮在 GUI 线程中依次执行两个 `waitForConnected(2000)`，最坏会冻结约 4 秒。

现在：

- 使用 QtConcurrent 在后台探测控制口和数据口。
- 探测期间按钮禁用并显示状态。
- 结果只说明“端口可达”或“端口不可达”。
- 不再把 TCP 端口可达误标成真实采集 `Connected`。
- 顶部连接状态继续只由 SessionHub 的真实采集连接驱动。

## 11. 录制状态修复

### 11.1 手动录制与触发录制分离

新增 `m_triggeredRecordingActive`：

- 阈值触发启动的录制标记为 triggered。
- 工具栏手动启动的录制标记为 manual。
- trigger auto-stop 只停止 triggered 录制。
- 用户打开 trigger 功能后，手动录制不会再被 auto-stop 误停。

### 11.2 回放模式保护

- SessionHub 在 replay source 下不执行阈值触发检查。
- UI 只允许在 `SessionHub::State::Live` 下响应 trigger。
- 回放状态即使 `isConnected()` 为真，也不会启动触发录制。

### 11.3 Pending record

- 未连接时点击录制会进入 pending 状态并尝试启动采集。
- 如果 `SessionHub::start()` 返回失败，立即清除 pending 并提示未录制。
- 录制错误、断开、停止或端点切换会清理 triggered/pending 状态。

## 12. SPI 后台队列与 shadow register

### 12.1 保留的硬件兼容行为

旧 Python `spi_mode.py` 已验证的增益命令保持不变：

- 增益全高：REC data `0x005E`。
- 增益全低：REC data `0x007E`。
- 每个真实写命令后发送一个 32-bit 全零 dummy。

本次没有修改 `ctre`、HTTP license server 或原 Python dummy server。

为保持硬件兼容，SPI 仍采用旧 Python 使用的“一条命令建立一次 TCP 连接”方式；发送过程已在后台 worker 中运行，不阻塞 Qt GUI。

### 12.2 每条写命令后补 dummy

ChannelMap 产生的外部批量命令原来只在两条真实命令之间插 dummy，最后一条后没有 dummy。

现在发送序列为：

```text
write0, dummy, write1, dummy, ..., writeN, dummy
```

与 Python 参考流程一致。

### 12.3 shadow register 同步

SpiControlPanel 每成功发送一条命令会发出 `spiCommandApplied`：

- ChannelMapPanel 解析 opcode、block、channel 和 data。
- REC `0x04`、DAC `0x06`、DAC_CT `0x1E` 写命令会同步到 `ChannelConfigModel`。
- 快速命令、直接 SPI、用户自定义命令和 ChannelMap 批量命令不再完全各自维护独立 shadow 状态。
- dummy 和不相关 opcode 自动忽略。

### 12.4 后台关闭

- SPI worker 每条命令前后检查 `m_destroying`。
- 单次 TCP connect/reply 均有超时上限。
- 析构时最多等待当前有界网络操作结束，不继续执行后续队列命令。

## 13. 配置持久化

### 13.1 第一页通道选择

ChannelMap 现在保存 `selected_globals`：

- 点击、框选、全选、清空和批量选择都会触发 500 ms debounce。

- 下次启动时恢复为 block/local pair 并同步到图形选择状态。
- 页面 shutdown 时如果 debounce 尚未触发，会立即完成最后一次保存。

### 13.2 Analyzer 与 Realtime

- Analyzer 的通道、采样率、刷新率、波形点数、FFT 点数、窗、DC bin、Sig bin、BW、Gain、TDM 和统计源继续使用 debounce 保存。
- 从第一页载入 Analyzer 通道后会保存并在运行中重建管线。
- 从第一页载入 Realtime 通道后现在会立即保存。
- Realtime 运行中应用通道或切换 TDM 时重启页面 sorter，避免旧 chunk 写入新通道状态。
